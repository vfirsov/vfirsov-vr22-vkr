# Статус проекта на 16.11.2026

Текущее состояние репозитория: материалы ВКР, frontend на Nuxt 4 с серверным рендерингом и отдельное API на Flask. Каталог читает 12 демонстрационных товаров из PostgreSQL через SQLAlchemy; реализованы таблицы категорий и товаров, миграция и начальное заполнение. БД подключена к API в Amvera через секрет `DATABASE_URL`. Заказы и авторизация не реализованы. Описание полной системы в [README.md](README.md) задаёт целевой результат.

Статус зафиксирован по коду и документации репозитория. Свежая проверка демо-стенда и прогон тестов в дату фиксации не выполнялись; что и как проверяется — в разделе «Сведения о проверках».

## Что реализовано

### Frontend — [`frontend/`](frontend/)

- Nuxt 4 (Vue 3, TypeScript), серверный рендеринг на Nitro (`node-server`), Docker-сборка.
- Страницы: стартовая `/`, каталог `/catalog` (SSR: товары запрашиваются у API при каждом рендеринге), страница неизвестного маршрута (404).
- Серверный маршрут `/healthz`.
- Настроенные проверки: `npm run typecheck`, `npm run build`, SSR-интеграционный тест `npm run test:ssr` (рендеринг данных API, реакция на недоступность API, 404).

### Backend — [`backend/`](backend/)

- Демо API на Flask 3 + Gunicorn, SQLAlchemy 2, Alembic, Python 3.12.
- Роуты: `GET /healthz`; `GET /api/catalog` — активные товары из БД при каждом запросе, `total`, `currency: "RUB"`, `Cache-Control: no-store`; при недоступной БД или незаданном `DATABASE_URL` — `503` с JSON `error`; неизвестный маршрут — `404` с JSON `error`.
- CORS: allowlist в `backend/app.py` (домен демо-frontend и локальные адреса); остальные Origin CORS-заголовков не получают.
- Таблицы `categories` и `products`, миграция `0001_catalog`, начальное заполнение из `catalog.json` (7 категорий, 12 товаров; существующие данные не перезаписываются).
- Тесты unittest на временной SQLite: контракт каталога, чтение при каждом запросе, `503`, повторный `prepare`, соответствие миграции моделям, ограничения БД, CORS, `healthz` и 404.

### Инфраструктура

- Dockerfile для frontend и backend, `amvera.yaml` для обоих проектов Amvera.
- Демо-стенд: проекты `tea-shop-frontend-demo` и `tea-shop-api-demo`, PostgreSQL проекта `vkr-demo`; переменные `NUXT_PUBLIC_API_BASE_URL` и секретная `DATABASE_URL`.
- Обновление стенда ручное; webhook GitHub → Amvera не настроен.

## Известные ограничения

- Frontend: реализованы стартовая страница, каталог (SSR, 12 товаров из демо API) и страница неизвестного маршрута; корзина, вход и личный кабинет недоступны.
- Репозиторий проекта frontend в Amvera наполняется через MCP без `package-lock.json` (файл не передаётся через API); сборка выполняет `npm install` по точным версиям из `package.json`. При доставке кода через Git применяется `npm ci` по lock-файлу.
- Backend: реализовано чтение каталога из PostgreSQL через SQLAlchemy. Изменение товаров через API, заказы, оплата и доставка не реализованы.
- Нагрузочные показатели из ВКР не подтверждены для текущего кода и демо-стенда.
